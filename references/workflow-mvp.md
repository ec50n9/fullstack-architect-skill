# MVP Workflow (快速验证)

目标：用最短路径跑通核心闭环。**速度优先，欠账必登记。**

## Step 1: 选型

- **不背清单**：选型原则只有三条——生态活跃、维护健康、类型安全优先。具体库的版本与兼容性以 registry 事实为准（`bun info <pkg> dist-tags` / `bun info <pkg>@<version> peerDependencies`），用前验证，禁止凭记忆引用版本号和 API 签名。
- 激进使用三方库实现框架和基础功能（UI、表单、校验、状态、路由），只为核心业务闭环手写代码。
- 工具链现代且统一：一个运行时/包管理器、一个构建工具，不混用。

## Step 2: 实现纪律

- 允许 hack、硬编码、复制粘贴——但**每个妥协必须当场登记 `DEBT.md`**：欠了什么、为什么现在不还、什么信号触发偿还。未登记的妥协视为违规。（登记的意义：MVP 的妥协没有偿还压力就会烂成遗留；`DEBT.md` 是晋升基建时唯一的还账清单。）
- 速度不豁免三类底线：密钥进仓库、跳过输入校验导致数据损坏、丢失用户数据的操作。
- 核心闭环之外的功能一律不做，转入「明确不做清单」。

## Step 3: Proposal (必须暂停)

**【禁止输出代码】** 输出 Markdown 预案并暂停：

1. **选型清单**：工具链 + 三方库，各自承担什么。
2. **闭环路径**：核心闭环的实现步骤。
3. **欠账预告**：计划内已知妥协，预登记进 `DEBT.md`。
4. **结尾附加提示符**：
   `🚀 MVP 预案已生成。请回复：[1] 执行 [2] 调整选型或范围 [3] 补充缺失的上下文信息。`

## Step 4: Execution & 晋升信号

仅当用户回复 `[1]` 时继续。交付时附带：

- `DEBT.md` 全量清单。
- **晋升信号提醒**：出现真实用户 / 外部数据 / 多人协作 / 收入时，提示进行晋升审计（清偿 DEBT、评估三方库留换、规划数据迁移），切换到基建档，后续任务走 [workflow-feature.md](workflow-feature.md)。
